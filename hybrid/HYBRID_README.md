# 混合 TCP/UDP 協議聊天室

## 📚 為什麼同時使用 TCP 和 UDP?

### TCP 的特性與用途
**傳輸控制協議 (TCP)**
- ✅ **可靠傳輸**: 保證資料完整送達,無丟包
- ✅ **順序保證**: 封包依序到達
- ✅ **錯誤檢測與重傳**: 自動重送遺失的封包
- ✅ **流量控制**: 避免接收端過載
- ❌ **延遲較高**: 三次握手、確認機制增加延遲
- ❌ **開銷較大**: 連線維護、狀態管理

**在本專案中 TCP 用於**:
1. 聊天訊息傳送 - 必須確保每條訊息都送達
2. 用戶登入/登出 - 重要的連線管理
3. 系統通知 - 如「XXX 加入聊天室」
4. 指令處理 - 如 `/users`, `/quit`

### UDP 的特性與用途
**用戶資料報協議 (UDP)**
- ✅ **低延遲**: 無連線建立,直接發送
- ✅ **輕量級**: 標頭只有 8 bytes
- ✅ **適合即時應用**: 語音、視訊、遊戲
- ✅ **群播支援**: 可以一對多傳輸
- ❌ **不可靠**: 可能丟包、重複、亂序
- ❌ **無流量控制**: 可能造成網路壅塞

**在本專案中 UDP 用於**:
1. 心跳包 (Heartbeat) - 每 5 秒一次,丟包不影響
2. 正在輸入狀態 - 即時性比完整性重要
3. 在線狀態檢測 - 快速判斷用戶是否在線
4. Ping/Pong - 延遲測試

## 🔧 使用方法

### 啟動伺服器
```powershell
python hybrid_server.py
```

預設會監聽:
- TCP Port 5678 (聊天訊息)
- UDP Port 5679 (狀態更新)

### 啟動客戶端

**命令列模式**:
```powershell
python hybrid_client.py Alice
```

**GUI 模式**:
```powershell
python hybrid_client.py Bob --gui
```

**自訂埠號**:
```powershell
python hybrid_client.py Charlie --tcp-port 5678 --udp-port 5679 --gui
```

## 🧪 測試與驗證

### 測試 1: TCP 可靠性
1. 發送長訊息 (超過 buffer size)
2. 觀察訊息是否完整送達
3. **預期**: 所有訊息完整無損

### 測試 2: UDP 即時性
1. 在輸入框打字 (不要按發送)
2. 觀察其他客戶端是否顯示「正在輸入」
3. **預期**: 即時顯示,偶爾丟包也不影響

### 測試 3: 心跳機制
1. 啟動客戶端
2. 等待 30 秒不操作
3. 伺服器端會持續收到心跳包
4. **預期**: 客戶端保持在線狀態

### 測試 4: 斷線偵測
1. 強制關閉客戶端 (不正常離開)
2. 觀察伺服器在 30 秒後偵測到超時
3. **預期**: 伺服器自動移除該客戶端

## 🎯 設計理念

### 為什麼不全用 TCP?
- TCP 的確認機制會增加延遲
- 心跳包每 5 秒一次,不需要可靠性
- 「正在輸入」狀態即時性比完整性重要
- UDP 可以降低伺服器負載

### 為什麼不全用 UDP?
- 聊天訊息必須確保送達
- 登入/登出等重要事件不能丟失
- 用戶會期望看到完整的對話歷史
- UDP 需要自己實作可靠性機制 (複雜)

### 最佳實踐
✅ **關鍵資料用 TCP**: 聊天內容、用戶資料、指令
✅ **即時狀態用 UDP**: 心跳、輸入狀態、在線檢測
✅ **混合使用**: 發揮兩者優勢,降低各自缺點

## 🔍 協議細節

### TCP 訊息格式
```
[4 bytes 長度][訊息內容]
```
- 使用長度前綴協議
- 支援超過 buffer size 的大訊息
- 確保訊息完整性

### UDP 訊息格式
```
COMMAND|nickname|data
```

支援的指令:
- `HEARTBEAT|Alice` - 心跳包
- `TYPING|Alice` - 正在輸入
- `REGISTER|Alice` - 註冊 UDP 位址
- `PING` - 延遲測試
