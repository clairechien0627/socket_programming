# 多埠口聊天室 (Multi-Port Chat System)

## 📋 專案說明

這是一個展示**多埠口架構 (Multi-Port Architecture)** 的安全聊天室應用程式。不同的功能使用不同的網路埠口，實現功能隔離和效能優化。

### 問題
你的系統是否能做到 Nonblocking，在處理多用戶或龐大的 message 時，其他功能會不會被卡住？

### 答案
✅ **可以！** 本系統使用多種技術實現 nonblocking。

本專案完成以下作業要求:

### ✅ +5 Multi Port Listing（Different Port for Different Method）

## 💡 Nonblocking 實作

### 1. 多執行緒架構
```
伺服器:
├─ Thread-1: 處理 Alice
├─ Thread-2: 處理 Bob
└─ Thread-3: 處理 Charlie

✅ Alice 發訊息不會卡住 Bob
✅ 100 個用戶可以同時聊天
```

### 2. 多埠口分離

#### 問題場景
單埠口架構:
```
Alice 正在傳送 100MB 檔案
→ TCP 6678 被阻塞
→ Bob 的聊天訊息要等很久 ❌
```

#### 解決方案
多埠口架構:
```
TCP 6678: 聊天訊息
UDP 6679: 狀態更新
TCP 6680: 檔案傳輸

Alice 用 TCP 6680 傳檔案
Bob 用 TCP 6678 聊天
→ 兩者互不影響 ✅
```

### 3. GUI 非同步設計
```
Thread-1: 接收訊息 (background)
Thread-2: GUI 主執行緒 (用戶操作)

✅ 接收訊息時用戶還能輸入
✅ GUI 不會凍結
```

## 🏗️ 架構設計

### 為什麼需要多埠口？
- 聊天、狀態、檔案各自獨立
- 一個功能故障不影響其他功能
- 檔案傳輸不阻塞即時聊天
- UDP 心跳減少 TCP 開銷
- 可以針對不同埠口設定不同的優先級
- 可以分別限流、監控

### 埠口分配

| Port | 協定 | 功能 | 原因 |
|------|------|------|------|
| **6678** | TCP | 聊天訊息 | 需要可靠傳輸、順序保證 |
| **6679** | UDP | 狀態更新 | 低延遲、可容忍遺失 |
| **6680** | TCP | 檔案傳輸 | 大量資料、不阻塞聊天 |

## 📊 技術實作

### 伺服器端
```python
# 三個獨立的監聽埠口
TCP 6678: handle_tcp_client()      # 聊天訊息
UDP 6679: handle_udp_messages()    # 狀態更新
TCP 6680: handle_file_transfer()   # 檔案傳輸

# 每個埠口在獨立的執行緒中運行
threading.Thread(target=file_transfer_server, daemon=True)
threading.Thread(target=handle_udp_messages, daemon=True)
```

### 客戶端
```python
# 三個獨立的連線
self.tcp_sock → 連到 6678 (聊天)
self.udp_sock → 連到 6679 (狀態)
file_sock → 連到 6680 (傳檔時才連)

# 檔案傳輸在背景執行緒進行
threading.Thread(target=self.send_file_thread, daemon=True)
```

### 檔案傳輸協定

#### 1. Metadata 交換
```json
{
    "sender": "Alice",
    "filename": "report.pdf",
    "filesize": 1024000,
    "recipient": "all"
}
```

#### 2. 分塊傳輸
- 每次傳送 8192 bytes (FILE_CHUNK_SIZE)
- 每 20% 回報進度

#### 3. 伺服器回應
```json
{
    "status": "success",
    "message": "檔案已廣播"
}
```

## 🐛 已知限制

### 模擬實作
- 檔案傳輸是**模擬版本**
- 實際有傳輸檔案資料,但伺服器不儲存
- 目的是展示多埠口架構,而非完整的檔案系統

### 為什麼模擬？
1. **時間考量**: 完整實作需要 10+ 小時
2. **重點展示**: 作業要求是"多埠口",不是"檔案系統"
3. **足夠證明**: 已經有真實的 TCP 6680 連線和資料傳輸

### 真實部分
✅ 伺服器真的監聽 6680 埠口
✅ 客戶端真的連線到 6680
✅ 真的讀取檔案並分塊傳送
✅ 真的不阻塞聊天功能

### 模擬部分
❌ 伺服器不儲存檔案到硬碟
❌ 接收者不能真的下載檔案
❌ 沒有檔案完整性校驗 (MD5/SHA256)
