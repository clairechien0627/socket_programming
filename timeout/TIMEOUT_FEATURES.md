# 閒置超時功能說明

## 📌 功能概述

本系統實作了多層級的超時檢測機制，防止資源被閒置連線耗盡。

---

## 🎯 實作的超時機制

### 1. **閒置超時 (Idle Timeout)** ⭐ NEW

#### 追蹤機制
- 每個客戶端記錄 `last_activity` 時間
- 每次收到 TCP 訊息時更新活動時間
- **注意**: UDP 心跳不算作活動時間 (只用於連線檢測)

#### 超時階段

| 階段 | 閒置時間 | 動作 |
|------|---------|------|
| ⚠️ **警告** | 5 分鐘 | 發送警告訊息給客戶端，提醒即將斷線 |
| 🔴 **斷線** | 10 分鐘 | 自動關閉連線，釋放資源 |

#### 警告訊息範例
```
[system] ⏰ 警告: 你已閒置 5 分鐘，超過 10 分鐘將自動斷線
```

**短時間範例** (測試用):
```
[system] ⏰ 警告: 你已閒置 30 秒，超過 60 秒將自動斷線
```

#### 斷線訊息範例
```
[system] ⏰ 你已閒置 10 分鐘，連線已被關閉
```

**短時間範例** (測試用):
```
[system] ⏰ 你已閒置 60 秒，連線已被關閉
```

---

### 2. **心跳超時 (Heartbeat Timeout)**

- **檢測週期**: 每 10 秒
- **超時時間**: 30 秒
- **用途**: 檢測網路斷線或客戶端崩潰

---

## 🔧 技術細節

### 客戶端資料結構
```python
clients[nickname] = {
    'tcp_conn': socket,           # TCP 連線
    'crypto': CryptoManager,      # 加密管理器
    'udp_addr': tuple,            # UDP 地址
    'last_heartbeat': float,      # 最後心跳時間 (UDP)
    'last_activity': float,       # 最後活動時間 (TCP) ⭐ NEW
    'idle_warned': bool           # 是否已發送閒置警告 ⭐ NEW
}
```

### 活動時間更新時機
✅ **會更新活動時間的動作**:
- 發送聊天訊息
- 執行命令 (`/users`, `/quit` 等)
- 接收任何 TCP 加密訊息

❌ **不會更新活動時間的動作**:
- UDP 心跳 (HEARTBEAT)
- UDP 輸入狀態 (TYPING)

### 檢查執行緒
```python
# 閒置檢查執行緒 - 每 30 秒檢查一次
idle_thread = threading.Thread(target=check_idle_timeout, daemon=True)
idle_thread.start()
```

## ⚙️ 自訂超時時間

修改 `timeout_server.py` 中的常數 (第 32-33 行)：

```python
# 閒置超時設定
IDLE_WARNING_TIMEOUT = 300   # 5 分鐘 (秒)
IDLE_DISCONNECT_TIMEOUT = 600  # 10 分鐘 (秒)
```

### 建議設定值

| 使用場景 | 警告時間 | 斷線時間 |
|---------|---------|---------|
| 開發測試 | 30 秒 | 60 秒 |
| 快速測試 | 60 秒 | 120 秒 |
| 一般聊天室 | 5 分鐘 (300 秒) | 10 分鐘 (600 秒) |
| 嚴格管理 | 3 分鐘 (180 秒) | 5 分鐘 (300 秒) |
| 寬鬆管理 | 15 分鐘 (900 秒) | 30 分鐘 (1800 秒) |

### 🎨 智能時間顯示

系統會自動根據超時時間選擇最合適的單位：
- **< 60 秒**: 顯示「X 秒」
- **≥ 60 秒**: 顯示「X 分鐘」

```python
# 範例 1: 30 秒
IDLE_WARNING_TIMEOUT = 30
# 顯示: "⚠️ 警告: 你已閒置 30 秒，超過 60 秒將自動斷線"

# 範例 2: 5 分鐘
IDLE_WARNING_TIMEOUT = 300
# 顯示: "⚠️ 警告: 你已閒置 5 分鐘，超過 10 分鐘將自動斷線"
```

## 🛡️ 資源保護效果

### 防止資源耗盡
- ✅ 自動清理閒置連線
- ✅ 避免殭屍連線佔用資源
- ✅ 防止惡意客戶端長期佔用連線

### 效能影響
- 檢查執行緒每 30 秒運行一次
- 時間複雜度: O(n)，n = 客戶端數量
- 對伺服器效能影響極小

## 📝 注意事項

1. **警告只發送一次**: 避免重複打擾用戶
2. **活動後重置**: 任何 TCP 訊息都會重置閒置計時
3. **心跳不算活動**: UDP 心跳只用於偵測連線，不影響閒置判定
4. **執行緒安全**: 使用 `clients_lock` 保護共享資料
5. **優雅斷線**: 發送通知後才關閉連線
